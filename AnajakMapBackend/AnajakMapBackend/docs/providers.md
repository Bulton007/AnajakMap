Production and development are explicit profiles. Only `dev` and `test` activate deterministic results. Outside those profiles, required integration credentials fail startup; optional external calendar synchronization reports 503 when unconfigured. Errors never substitute development results.

Provider adapters are normalized HTTP contracts, allowing vendor selection without exposing credentials to Flutter. They are complete HTTP clients for the contracts below; they are not direct OpenAI, Google Maps, FCM or airline SDK adapters. A production endpoint must implement the specified contract or an integration bridge must translate the selected vendor API. `PROVIDER_URL` and `PROVIDER_KEY` are scoped independently per service, rather than one shared provider credential. URLs should use HTTPS in production. Requests carry `Authorization: Bearer <key>` and trace context. Connection timeout is three seconds, response-header timeout fifteen seconds. GET requests retry at most three times; AI jobs and persisted delivery workers bound POST retries. Push/email/calendar endpoints must honor their idempotency keys. The S3 adapter uses real AWS Signature V4 and was verified against local MinIO using authenticated uploads and downloads.

AI Guide uses `POST /itinerary` with `{trip, preferences, places}`. Response: `{activities:[{title,startsAt,endsAt,latitude,longitude,source}],source,updatedAt,estimate}`. Current place facts originate in Discovery; preserve factual source references in stop responses. Other operations are `POST /chat`, `/translation`, `/vision`, `/voice`, `/receipt`, `/reservation`, `/recap`. Inputs are JSON maps. Vision/voice may refer to media uploaded through the authenticated media API; the backend sends bytes as `imageBase64` plus `mimeType`. Document extraction uses `documentBase64` and `mimeType`. Translation takes text and targetLanguage. Vision returns possibleLandmarks with confidence, explanation, and extractedText; uncertainty must be explicit. Receipts return amount and currency. Reservations return extracted provider/reference/time fields for user confirmation. Recaps return text and remain editable. Voice adapters may return transcript and/or encoded audio. No provider credentials are sent to clients.

Discovery uses `POST /places` with query/page/size and expects a JSON array of `{id,name,latitude,longitude,source,updatedAt}`. `/nearby` takes coordinates/radius. `/weather`, `/food`, `/culture`, `/routes`, `/transport` take query parameters normalized into JSON. Return source/update metadata on current travel facts and mark duration/fare estimates. Provider caching is disabled; enable the internal cache path only after reviewing the selected provider's storage policy.

Expense currency uses `CURRENCY_PROVIDER_URL` / `CURRENCY_PROVIDER_KEY`, `POST /currency` with `{from,to,amount}` and requires rate/source/updatedAt. The dev adapter supports USD/KHR/EUR with clearly marked fixture rates. Production responses should provide exact decimal representations, currency and estimate metadata.

Identity email uses `MAIL_PROVIDER_URL` / `MAIL_PROVIDER_KEY`, `POST /email` with recipient/template/code. Templates are VERIFY or RESET. The request's Idempotency-Key is the delivery ID. Queue secrets are encrypted and deleted after delivery/expiry. Notification push uses its own PROVIDER_URL/KEY and `POST /push` with tokens/title and the same stable delivery-key contract. Optional Trip calendar uses `CALENDAR_PROVIDER_URL` / `CALENDAR_PROVIDER_KEY`, `POST /calendar/sync` with tripId/calendar. User OAuth authorization for a chosen calendar vendor should be managed by that integration endpoint.

Object storage uses OBJECT_URL, OBJECT_REGION, OBJECT_BUCKET, OBJECT_ACCESS_KEY and OBJECT_SECRET_KEY. Create a private bucket first (Compose does this). Configure least-privilege bucket credentials, encryption at rest and lifecycle policies. The app stores object IDs and MIME/size metadata in its own schema. Local Compose uses MinIO; production can use an S3-compatible endpoint. Uploaded types and size are checked, but a production ingestion pipeline should inspect actual file signatures and run the organization's chosen malware scanner.
