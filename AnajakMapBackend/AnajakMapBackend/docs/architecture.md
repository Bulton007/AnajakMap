AnajakMap uses Java 21, Spring Boot 3.5.16, Maven 3.9.11 and springdoc 2.8.16. Boot manages the Spring Security, Hibernate, Redis, RabbitMQ, Oracle JDBC and Flyway dependency versions. Compatibility references: https://docs.spring.io/spring-boot/3.5/system-requirements.html and https://springdoc.org/v2/. The installed dependency set is recorded by Maven; run `./mvnw dependency:tree` to inspect it.

Each service is an independent executable jar. Identity owns accounts, verification/reset codes, refresh tokens and preferences. Trip owns trips, draft/approved itinerary versions, activities, group roles, votes, calendar events, proposals, short-lived location consent and offline snapshots. AI Guide owns conversations, messages, phrases, uploaded media and durable jobs. Discovery owns journey legs and read-only provider queries. Expense owns budgets, expenses, splits and receipts. Reservation owns document metadata and confirmed booking records. Journal owns private entries, media and visits. Notification owns device tokens, reminders, delivery attempts and its event inbox. Gateway owns routing and rate limiting.

The platform module contains technical HTTP, security, logging, OpenAPI, audit, idempotency and event infrastructure. It contains no JPA entities or business repositories. Identity and Trip use JPA with optimistic locking; the other services use parameterized JDBC for their local domain tables and conditional version updates. No service queries another service's schema. Cross-service authorization checks propagate the signed user JWT and use Trip's access API. HTTP calls complete before local business transactions; failed remote calls cannot be rolled back locally.

Oracle development uses one instance and nine schema owners. The recommended startup script runs migrations with owner credentials and creates nine separate application users with access only to their service's schema. Runtime users have SELECT/INSERT on BUSINESS_AUDIT and cannot change its trigger or issue audit UPDATE/DELETE. The database trigger additionally rejects UPDATE/DELETE by schema owners. DBA credentials remain outside application containers. Production runs migration Jobs separately, grants runtime permissions through a DBA, and disables Flyway in service Deployments.

Audit rows and outbox rows commit in the business transaction. Audit fields are explicitly selected at each call site: identifiers, versions, role/consent state, amounts, currency, or timestamps. Private messages, journal content, documents, passwords and tokens are excluded. Failed attempts are logged separately, without request bodies. Email codes queued for delivery and push device tokens are AES-GCM encrypted; only hashed refresh tokens and verification/reset codes are used for authentication comparisons. Access tokens expire after 10 minutes; logout/reset revoke refresh sessions, and already-issued access tokens remain valid until expiry.

RabbitMQ is the durable broker. It provides persistent messages, publisher confirms, durable quorum queues and dead-letter exchanges. The outbox retries eight times with a bounded delay and marks exhausted rows DEAD for operator inspection. Publication can repeat if the process crashes after broker acknowledgement; Notification inserts the event ID and schedules deliveries in a single transaction and ignores duplicates. Itinerary approval and trip invitation events schedule notifications. Consumer failures retry four times before broker dead lettering. Delivery requests carry the stable delivery ID as the provider idempotency key, retry at most five times, and retain a terminal DEAD record. Production should use a three-node RabbitMQ operator installation, not the single-node development topology.

Generation jobs are persisted before work starts. AI calls run outside transactions, retry transient failures at most three times, and expose QUEUED/RUNNING/SUCCEEDED/FAILED. Bean validation rejects missing stops, coordinates and sources; time validation rejects invalid durations. Trip independently rejects overlaps and activities outside the trip. Grounded place results are sent to the AI provider. Replanning includes the current calendar, provider weather and supplied delays/skipped stops/preferences; saving creates a proposal, and only approval switches the active itinerary. Stale proposals fail with 409. Interrupted jobs become FAILED after a lease timeout, allowing users to submit a new request.

Itinerary activities supply calendar entries; they are not duplicated in a calendar table. Standalone calendar events have a separate purpose and are checked against both approved activities and existing events under a trip lock. Travel instants use UTC-compatible TIMESTAMP WITH TIME ZONE; IANA zones remain on trips/events/reservations/legs. Dates are local travel dates. Money uses NUMBER(14,2) and Java BigDecimal; currencies are explicit ISO codes. Totals are grouped by currency rather than summed across currencies.

Redis is used for atomic expiring request/attempt limits and a 60-second trip calendar cache. Trip authorization runs before cache reads; cache keys include the Oracle version, and affected entries are evicted only after transaction commit. Redis cache outages load the authoritative Oracle data. Provider results are not cached by default, avoiding unsupported caching of third-party data. Discovery contains a TTL-bounded cache path that can only be enabled for a provider contract that permits it. Permanent state, jobs and delivery retries live in Oracle. Uploaded bytes live in private S3-compatible object storage; authenticated APIs authorize downloads from Oracle metadata. Reservation, journal and receipt uploads attempt S3 cleanup after metadata rollback; a process crash or failed cleanup can still leave an unreferenced object; configure an object lifecycle/orphan reconciliation policy before production use.

The gateway passes status codes and content types through and limits request size. Every service independently validates JWT signature, issuer, audience and expiry. Gateway readiness includes downstream readiness; services' readiness includes Oracle, Redis and RabbitMQ. Structured stdout and rotating file logs carry service, trace, method, path, status, duration and actor when available. Volumes retain files across container replacement. HTTP clients propagate X-Trace-ID; event headers and AI jobs preserve it. Actuator exposes protected Prometheus metrics. Production must enable cluster log collection and encrypt internal traffic with a service mesh or TLS endpoints; development's isolated Docker network uses HTTP. No paid or external deployment is performed by this project.
